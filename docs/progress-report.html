Auzy AI v2

The new engine behind the Auzy patient chat: what we built, what it costs, how it was tested, and what the team needs to decide next.

Summary

  • The current chat sends every call to Claude Opus 4.8 and costs about $1.58 per conversation. 85% of that is Cognisys, which re-analyses the patient after almost every reply.
  • The current chat has no safety handling: no crisis detection, no emergency information for the patient, no alert to the care team.
  • Auzy AI v2 keeps everything patients and clinicians use today and changes how Claude is called underneath: safety checks in four languages, the cheaper model for routine messages, prompt caching, and one analysis per conversation instead of one per reply.
  • Measured with real calls: a routine English conversation costs about 0.4–1.5¢, a 10-message Derja conversation 9.4¢, a short crisis conversation 6.2¢.
  • A budget governor keeps the average at $50–80 per 1,000 conversations whatever the mix of languages, and never limits crisis handling.
  • It is delivered as an API that auzy-backend calls. Only the profiles listed as test accounts use it; everyone else keeps today's chat, and one setting switches it off.
  • Tested: 81 automated tests and a full local run with the real processes (API, MongoDB, risk service), plus 3 live runs of the engine with real Claude calls. Not yet run inside Auzy. The Arabic and Derja material still needs review by native-speaker clinicians.

Other findings in the live code:

  • Cognisys waits only 10 seconds between runs (COOLDOWN_SECONDS = 10), while a comment says 5 minutes. That is why it runs after almost every reply.
  • The Cognisys schema leaves out confidence, source, unit and dimension factors, so those fields are always empty.
  • The chat-language switch merges a hidden instruction into the main prompt, which resets the cache.
  • Only the last 10 messages are sent to Claude, a window that shifts every turn and so can never be cached.
  • When a reply shows professional cards, the reply text is replaced by a fixed sentence. That could erase a safety message.

What we built: risk detection

Every patient message is checked on our own server before Claude sees it. These checks cost nothing per message and take about 26 ms.

The risk model

A multilingual language model (XLM-R) fine-tuned on that data. It reads each message and scores 8 states: normal, anxiety, depression, suicidal, self-harm, trauma, stress, loneliness or grief. It runs on an ordinary server CPU.

Crisis phrase lists

Phrase lists in English, French, Arabic and Derja catch explicit statements about suicide, self-harm, harming someone else and abuse. Derja spellings are normalised first, so n7eb nmout, nheb nmout and N7ebb nemout all match. Everyday phrases that look similar, such as ضربني البرد ("I caught a cold"), are tested and do not trigger.

The lists and the model run together in a small Python service, auzy-risk. Long messages are scored in pieces so a risk sentence at the end is not cut off.

Known limits

  • The model never saw reviewed Derja data, so for Derja it relies mostly on the phrase lists.
  • It wrongly flags some ordinary messages, for example "I had something similar two years ago after my exams" (score 0.87). In v2 that only triggers a second opinion from Sonnet, never an alert.

Before building v2 we tested the design as a standalone Python assistant with real Claude calls. Each problem we found became a rule in v2.

What we built: the v2 engine

A Node service, the Auzy AI API, which auzy-backend calls for each patient message, plus the auzy-risk service. What patients and clinicians see stays the same:

  • personas (the consultant's assistant, or the platform default)
  • professional, appointment and test cards
  • credits: 1 per message, the same rule for every patient
  • the pre-diagnostic with a free consultation offer at 0 credits
  • Cognisys profiles, the master's library, Socket.IO and the chat language switcher

  S3 --> R

Safety rules

  • Risks covered: suicidal thoughts (including indirect ones), self-harm, harming someone else, abuse or violence, other acute crises.
  • An explicit crisis phrase escalates at once. Every other signal needs Sonnet's confirmation on the same message.
  • Escalation means: an alert to the care team (webhook), an emergency banner with 190 (SAMU) in the patient's language, Sonnet for every later reply, and an urgent clinician summary.
  • An escalation stays active until a clinician clears it. The care team is alerted once per conversation.
  • If Claude declines to answer, the patient still gets the emergency text and the team is alerted.
  • Claude never discusses methods of suicide, self-harm or violence, never names a diagnosis and never gives medication advice.

End of a conversation

When credits reach 0, or after 30 minutes without a message, one call produces three things that used to need three separate jobs:

  • Cognisys update: facts (now with confidence and source filled in), dimensions and the profile summary.
  • Clinician summary in French: concerns, symptoms with duration, sleep, appetite, functioning, history, risk and protective factors, suggested questionnaire, consultation status, and a short narrative. Urgent only when the patient's own words show risk.
  • Pre-diagnostic for the patient (at 0 credits, if eligible) with the free consultation offer.

The next conversation starts fresh, carrying the profile summary and the last few messages so the assistant keeps the context.

How it plugs into Auzy

  • auzy-backend sends a patient's messages to the API only if the profile is on the test list. Everyone else keeps today's chat. If the API can't be reached, today's chat answers.
  • auzy-backend gets five new files: a queue consumer, a small client, and internal routes for the three lookups, the Cognisys read and the delivery of each analysis. It also gets two small patches (the chat route and the user-message queue). No existing file is replaced.
  • The frontend gets one patch: the emergency banner stays visible while a conversation is escalated.
  • The API keeps its own database on Auzy's MongoDB. It never touches Auzy's data: lookups and saves go through auzy-backend with a shared secret.
  • The auzy-risk service runs as a separate container on the internal network (about 1.5 GB of RAM).
  • Staff endpoints: clinician summaries, a conversation's state, clearing an escalation, and a cost report.
  • Rollback: one setting in auzy-backend (AI_V2_ENABLED=false).

Budget controls

The goal set on 27 October: $50–80 per 1,000 conversations. A conversation here is one sitting: from the first message until credits run out or 30 minutes of silence.

Quality levelWho writes routine repliesCost per 10-message conversation
EconomyHaiku for everyoneEnglish/French 0.3–1.5¢; Arabic/Derja about 4.6¢
Standard (starting level)Sonnet for Arabic/Derja, Haiku for English/FrenchEnglish/French 0.3–1.5¢; Arabic/Derja 9.4¢ (measured)
PremiumSonnet for everyoneEnglish/French about 5.3¢; Arabic/Derja 9.4¢
  • Budget governor. Once a day it reads the real average cost of the last 7 days from the cost ledger. Above $80 per 1,000 it moves one level cheaper at once; below $50 it moves one level better, at most once every 3 days. Nothing changes before 50 finished conversations.
  • 15¢ ceiling per conversation. Past it, routine replies and the analysis switch to Haiku.

Safety comes first

The ceiling and the governor never touch crisis handling. Second opinions, escalated conversations and urgent summaries always use Sonnet, even past 15¢. This default needs the team's confirmation (see the questions below).

Quality in the live tests

What worked

  • The first reply tells the patient that the conversation is summarized for the care team.
  • Asked about a test, the assistant showed the PHQ-9 card; asked for a professional, it showed professional cards with a short introduction.
  • The risk model's false signal produced a calm reply and no alert.
  • For the Derja abuse message (Rajli yadhrabni kol lila), the team was alerted at once. The reply asked whether she was safe and whether her husband was nearby, gave 190, and suggested reaching a trusted person. The urgent summary noted that her safety at home was unknown.
  • In the 10-message Derja conversation, "I feel worthless" led to a gentle safety question and no false alarm. The patient's denial was respected, and the closing reply mentioned the pre-assessment and the free 15-minute consultation.

Fixed after the live tests

  • Arabic letters inside Latin-script Derja words, and whole Arabic words inside a Latin-script reply, are now converted to Arabizi.
  • The closing reply at 0 credits now always mentions the pre-assessment and the free consultation.
  • Short Derja messages written with few numerals were not recognised as Derja.

Still open

  • A summary translated 3amin (two years) as "one year". Derja summaries need native review.
  • The pre-diagnostic for a Derja-speaking patient came out in French.
  • Some Derja wording in replies is unusual (for example moh'adtha for "conversation").

Questions for the team

What share of patients write in Arabic or Derja?

This decides the quality level the budget allows. Above about 70%, the budget pushes Derja replies back to Haiku.

Should the end-of-conversation analysis be made cheaper?

It is 4.3¢ of the 9.4¢ in a Derja conversation. Sonnet with less thinking and a shorter output should bring a Derja conversation to about 8¢, keeping Derja replies on Sonnet even with a mostly Derja user base.

Recommended, after one more measurement (about $0.05) to check summary quality.

Which language should a Derja speaker's pre-diagnostic use?

It currently comes out in French. Options: French, or Derja in the script the patient used.

Do we confirm that safety comes before the 15¢ ceiling?

Today a person in crisis keeps Sonnet, the alert and the urgent summary even past 15¢. The alternative is a strict 15¢ for every conversation.

Recommended: keep safety first.

Should the assistant learn from real conversations?

With patient consent and a few minutes of clinician feedback a day, a weekly job could improve the risk model and Haiku's Derja, so Derja conversations could cost about half. Each upgrade would ship only if it catches at least as many people at risk.

Suggested first step: a consent checkbox, clinician feedback screens and a Derja glossary.

Who may read clinician summaries?

The staff views need a separate staff token, and nobody has it by default. Who should hold it, and should consultants later see only their own patients?

How should escalations reach the care team?

Today: a webhook to a channel the team watches. An in-app notification for the assigned consultant needs a new notification type.

Which emergency numbers should patients see?

190 (SAMU) is configured. Abuse cases may also need a police or violence-support number; the clinical team should confirm which.

Before real patients use it

  • clinicalNative-speaker clinicians review the Arabic and Derja crisis phrases, the emergency texts, the assistant's instructions and the summary rules.
  • clinicalReview the 400-message Derja sample, then retrain the risk model with it.
  • legalConsent wording, data retention, and INPDP authorisation for processing health data.
  • operationsA named person on call for escalations, and the escalation webhook pointed at a channel they watch.
  • technicalCheck the tool field lists against the real Profile, Appointment and test models.
  • technicalCompare v2 replies with today's Opus replies on consented test conversations.
  • technicalDecide who holds the staff token for summaries and costs.
  • technicalBuild both container images on Auzy's server and run the API as a single instance (its lock and scheduler are in-process).
  • securityReplace the Anthropic API key used during testing: it was shared in a chat session.

Next steps

  1. Install the API and auzy-risk on a test server, following the transfer steps in the package README, and check /v1/health.
  2. Add the kit to auzy-backend, list the test accounts, and chat in each language using the checklist in auzy-ai-v2/README.md.
  3. Clinical review of the Arabic and Derja material, the Derja sample and the summary rules; retrain the risk model.
  4. Compare reply quality with the current chat on consented test conversations, then widen the test list.
  5. Go live with the cost report (/v1/costs) and the escalation channel monitored from day one.
  6. If agreed, start the learning loop: consent, clinician feedback, weekly upgrades with a safety check.
